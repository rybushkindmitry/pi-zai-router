# ADR-0001: Код — в git-пакете, деплой-политика — в локальных настройках

- Статус: принято
- Дата: 2026-10-06
- Supersedes: —

## Контекст

Расширение роутинга жило как локальный файл `~/.pi/agent/extensions/zai-router.ts`.
Одновременно вскрылось, что при диспаче сабагентов модели выбираются вслепую:
скилл superpowers требует указывать модель явно, но не говорит какой, а
pi-subagents прямо декларирует «exact model names are deployment policy — put
them in settings, not package guidance». Нужны были: переиспользуемость между
машинами, версионирование и одна точка правды для логики роутинга. Пакеты pi
переносят только ресурсы (extensions/skills/prompts/themes) — `settings.json`,
каталог провайдеров и ключи они не распространяют.

## Решение

Опубликовать расширение как git-пакет с пином на теги
(`pi install git:github.com/rybushkindmitry/pi-zai-router@vX.Y.Z`):

- **код и логика роутинга** — в пакете (одна точка правды, версионирование);
- **деплой-политика** — в локальных настройках каждой машины: `defaultProvider`
  / `defaultModel` в `settings.json`, каталог моделей в `models.json`, ключи в
  `auth.json`/env; README даёт сниппеты для воспроизведения.

## Альтернативы

| Альтернатива | Причина отказа |
| --- | --- |
| Править SKILL.md superpowers (вписать модели туда) | git-пакет, обновления затрут правки; guidance pi-subagents прямо запрещает имена моделей в package guidance |
| `subagents.modelScope: { enforce: true, allow: ["zai/*"] }` | Режет переход на другого провайдера — тот же hardcode, только с отказом вместо фолбэка |
| Хардкод моделей в AGENTS.md | Самая жёсткая связка: при смене провайдера переписывать прозу; инструкции пользователя старше скиллов — риск расползания политики по файлам |
| `subagents.defaultModel` глобально | Нивелирует tiering: implementer получает дорогую complex-модель |
| npm-публикация | Отложено: git-тег покрывает версионирование; npm возможен позже без изменения архитектуры |

Для закрепления reviewer-сабагента выбран мягкий механизм
`agentOverridesByProvider` (секция активна только когда родительская сессия на
zai; при смене провайдера фолбэк — наследование модели родителя).

## Последствия

- (+) Версионирование с пинами: обновление чек-аута (`pi update --extensions`)
  не двигает ref; переход на новую версию — явная смена тега.
- (+) Все машины на одинаковой логике; история изменений — в git-логе.
- (−) Каждая новая машина требует одноразовой настройки по README (settings,
  models.json, ключи) — осознанный размен «код переиспользуем / политика
  локальна».
- (−) Нельзя держать локальный файл расширения и пакет одновременно: двойная
  регистрация виртуальной модели `zai/auto` — конфликт.
- (−) Пин на тег навсегда: забытый апгрейд = старый код. Смягчение — README
  явно описывает процедуру обновления.
