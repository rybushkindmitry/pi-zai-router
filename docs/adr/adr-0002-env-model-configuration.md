# ADR-0002: Модели роутера конфигурируются env-переменными

- Статус: принято
- Дата: 2026-10-06
- Supersedes: —

## Контекст

В оригинальном локальном файле провайдер и модели были константами
(`"zai"`, `"glm-5.3"`, `"glm-5.3-flash"`). Для публичного пакета это означало:
смена пары моделей (другая подписка, другой провайдер) = форк или правка кода.
При этом ADR-0001 закрепил, что конкретные имена моделей — деплой-политика,
которая не должна жить в коде пакета.

## Решение

Провайдер и модели читаются из окружения при загрузке расширения:

- `ZAI_ROUTER_PROVIDER` (default `zai`)
- `ZAI_ROUTER_COMPLEX_MODEL` (default `glm-5.3`)
- `ZAI_ROUTER_FAST_MODEL` (default `glm-5.3-flash`)
- `ZAI_ROUTER_QUIET=1` — отключение диагностического лога

Пустое или пробельное значение считается неустановленным и даёт дефолт
(`?.trim() ||`, фикс в v1.0.1 по итогам ревью).

## Альтернативы

| Альтернатива | Причина отказа |
| --- | --- |
| Константы в коде (v1.0.0) | Смена моделей = правка кода пакета; кроме того `??` пропускал пустую строку → загадочная ошибка «модель отсутствует в каталоге» на каждый запрос (найдено ревью, исправлено в v1.0.1) |
| JSON-конфиг-файл | Лишняя поверхность для трёх значений; деплой-политика и так живёт в локальных настройках pi — второе место конфигурации усложнило бы диагностику |
| Конфиг через settings.json pi | Схема settings принадлежит хосту; специфичные для расширения ключи туда класть нельзя |

## Последствия

- (+) Смена моделей/провайдера без форка пакета; дефолты — z.ai, как у автора.
- (+) Конфигурация видна в окружении процесса — легко проверить/переопределить
  в юнит-обвязке.
- (−) Переменные читаются **один раз при старте pi**: смена требует
  перезапуска сессии.
- (−) Пустое значение молча даёт дефолт — поведение задокументировано в README
  (осознанный выбор против падения при старте).
